# Telegram-бот для заявок — клининговая компания «Чисто»

Демо-бот на **Python 3.11 + aiogram 3**. Компания «Чисто» вымышленная.

Что умеет бот:

- **/start** — приветствие и главное меню: «Услуги и цены», «Частые вопросы», «Оставить заявку», «Контакты».
- **Услуги и цены** — список услуг с ценами.
- **Частые вопросы** — вопросы кнопками, по нажатию показывается ответ.
- **Оставить заявку** — пошаговая форма: имя → телефон (только российский номер, можно отправить кнопкой) → услуга → комментарий (можно пропустить) → проверка заявки с кнопками «Отправить» и «Изменить».
- Готовая заявка приходит **администратору** в Telegram и сохраняется в базу (файл `leads.db`).
- Команды администратора:
  - **/leads** — последние 10 заявок;
  - **/reload** — перечитать `texts.yaml` без перезапуска бота.
- Все тексты, услуги, цены, вопросы и контакты лежат в одном файле **`texts.yaml`**. Править их можно без программиста.

## Шаг 1. Создаём бота и получаем токен

Токен — это «пароль» бота. С ним программа управляет ботом.

1. Откройте Telegram и найдите **@BotFather** (у него синяя галочка).
2. Нажмите **Start** (или отправьте `/start`).
3. Отправьте команду `/newbot`.
4. Введите **название** бота, например: `Чисто — заявки на уборку`.
5. Введите **имя пользователя** бота — латиницей и обязательно с окончанием `bot`, например: `chisto_demo_bot`. Если имя занято, придумайте другое.
6. BotFather пришлёт сообщение с токеном. Он выглядит примерно так:

   ```
   7123456789:AAHk3x...длинная строка...Zq8
   ```

7. Скопируйте токен — он понадобится на шаге 5.

> ⚠️ **Никому не показывайте токен.** Кто его знает, тот может управлять ботом. Если токен «утёк» — в @BotFather отправьте `/revoke` и получите новый.

## Шаг 2. Узнаём свой Telegram ID

ID — это число, по которому бот понимает, что вы администратор. На этот ID будут приходить заявки.

1. Найдите в Telegram бота **@userinfobot**.
2. Нажмите **Start**.
3. Он ответит сообщением, где есть строка `Id: 123456789`. Это число и есть ваш ID — запишите его.

> ⚠️ **Важно:** после запуска своего бота обязательно откройте его и нажмите **Start** со своего аккаунта администратора. Telegram не разрешает ботам писать первыми — пока вы не нажали Start, заявки к вам не придут (но они всё равно сохранятся в базе, их видно по `/leads`).

## Шаг 3. Устанавливаем Python на Windows

1. Откройте сайт <https://www.python.org/downloads/windows/>.
2. Найдите **Python 3.11** (подойдёт и более новый — 3.12, 3.13) и скачайте **Windows installer (64-bit)**.
3. Запустите установщик. **На первом экране обязательно поставьте галочку «Add python.exe to PATH»** (внизу окна), затем нажмите **Install Now**.
4. Проверьте установку. Нажмите `Win + R`, введите `cmd`, нажмите Enter. В чёрном окне (это «командная строка») введите:

   ```bash
   python --version
   ```

   Должно появиться что-то вроде `Python 3.11.9`. Если пишет «не является внутренней или внешней командой» — переустановите Python и не забудьте галочку «Add to PATH».

## Шаг 4. Устанавливаем бота и зависимости

1. Распакуйте папку с ботом, например в `C:\chisto-bot`.
2. Откройте эту папку в Проводнике, щёлкните по **адресной строке** сверху, сотрите путь, введите `cmd` и нажмите Enter — откроется командная строка уже в нужной папке.
3. Создайте «виртуальное окружение» — отдельную папку для библиотек бота, чтобы они не смешивались с другими программами:

   ```bash
   python -m venv venv
   ```

4. Включите его:

   ```bash
   venv\Scripts\activate
   ```

   В начале строки появится `(venv)` — значит, всё получилось.

5. Установите библиотеки, которые нужны боту:

   ```bash
   pip install -r requirements.txt
   ```

   Подождите, пока установка закончится (около минуты).

## Шаг 5. Настраиваем файл .env

В файле `.env` хранятся секретные настройки: токен и ваш ID.

1. В папке бота сделайте копию файла `.env.example` и назовите её **`.env`** (точка в начале, без `.example`).

   Проще всего — командой в той же командной строке:

   ```bash
   copy .env.example .env
   ```

2. Откройте `.env` Блокнотом (правой кнопкой → «Открыть с помощью» → «Блокнот») и впишите свои значения:

   ```
   BOT_TOKEN=7123456789:AAHk3x...ваш токен...Zq8
   ADMIN_ID=123456789
   ```

   Без пробелов вокруг `=` и без кавычек.
3. Сохраните файл.

> 💡 Если Windows скрывает расширения файлов, Блокнот может сохранить файл как `.env.txt` — тогда бот его не увидит. Включите показ расширений: в Проводнике «Вид» → «Показать» → «Расширения имён файлов», и переименуйте файл в `.env`.

## Шаг 6. Запускаем бота

В командной строке (в папке бота, с включённым `(venv)`):

```bash
python bot.py
```

Если всё правильно, появится строка:

```
... [INFO] root: Бот @chisto_demo_bot запущен. Остановить: Ctrl+C
```

Откройте бота в Telegram и нажмите **Start**. Бот работает, пока открыто это окно. Чтобы остановить — нажмите `Ctrl + C`.

**Как запустить бота в следующий раз** (после перезагрузки компьютера): откройте командную строку в папке бота и выполните по очереди:

```bash
venv\Scripts\activate
```

```bash
python bot.py
```

> Компьютер с ботом должен быть включён — иначе бот не отвечает. Чтобы бот работал круглосуточно, разместите его на сервере (VPS), см. раздел ниже.

## Как редактировать texts.yaml

`texts.yaml` — обычный текстовый файл. В нём все тексты бота, услуги, цены, вопросы и контакты.

### Чем открывать

- На Windows — **Блокнотом** или (удобнее) бесплатным [Notepad++](https://notepad-plus-plus.org/). Сохраняйте в кодировке **UTF-8** (в Блокноте Windows 10/11 это кодировка по умолчанию).
- На сервере — командой `sudo nano /opt/chisto-bot/texts.yaml` (сохранить: `Ctrl+O`, Enter; выйти: `Ctrl+X`).

### Как применить изменения

Сохраните файл и **отправьте боту команду `/reload`** со своего аккаунта администратора. Бот ответит «✅ Тексты обновлены». Перезапускать бота не нужно.

Если в файле ошибка, бот ответит «❌ Тексты не обновлены» и подскажет, где проблема. При этом бот **продолжит работать со старыми текстами** — клиенты ничего не заметят. Исправьте файл и снова отправьте `/reload`.

### Правила, чтобы ничего не сломать

1. **Отступы — только пробелами** (не клавишей Tab). Вложенные строки сдвигаются на 2 пробела.
2. Длинный многострочный текст пишется после `|`, со сдвигом на 2 пробела:

   ```yaml
   contacts: |
     <b>📞 Контакты «Чисто»</b>

     Телефон: +7 (900) 000-00-00
   ```

3. Слова в фигурных скобках — `{name}`, `{phone}`, `{lead_id}` — это **подстановки**: бот заменит их на имя клиента, телефон и т.д. Не удаляйте и не переводите их.
4. Оформление текста:
   - `<b>жирный</b>`, `<i>курсив</i>`, `<u>подчёркнутый</u>`;
   - ссылка: `<a href="https://site.ru">текст ссылки</a>`;
   - каждый открытый тег нужно закрыть (`<b>` … `</b>`);
   - знаки `<` и `>` в обычном тексте пишите как `&lt;` и `&gt;`.
5. Если строка начинается со спецсимвола (`*`, `&`, `@`, `[`, `{`, `#`) или содержит `: ` — возьмите её в двойные кавычки: `"..."`.

### Примеры

**Изменить цену:** найдите нужную услугу и поменяйте строку `price`:

```yaml
  - name: "Мытьё окон"
    price: "от 450 ₽ за створку"
    description: "С двух сторон, вместе с рамами и подоконниками."
```

**Добавить услугу:** скопируйте блок из трёх строк и вставьте в раздел `services` с тем же отступом:

```yaml
  - name: "Уборка балкона"
    price: "от 1 500 ₽"
    description: "Мытьё пола, стен, остекления."
```

Новая услуга сразу появится и в «Услугах и ценах», и в форме заявки. Строку `description` можно не писать.

**Добавить вопрос в FAQ:**

```yaml
  - question: "Работаете в выходные?"
    answer: |
      Да, мы работаем ежедневно с 8:00 до 22:00.
```

Текст вопроса — это подпись кнопки, делайте его коротким (до ~40 символов).

**Удалить** услугу или вопрос — удалите весь блок целиком (все его строки).

> 💡 Перед правкой полезно сделать копию файла (`texts_backup.yaml`), чтобы при ошибке быстро вернуть как было.

## Запуск на VPS (Ubuntu) 24/7

VPS — это арендованный сервер в интернете, который работает круглосуточно. Подойдёт самый дешёвый тариф (1 ядро, 1 ГБ памяти) у любого хостинга с **Ubuntu 22.04 или 24.04**. После покупки хостинг пришлёт **IP-адрес** сервера и **пароль root**.

### 1. Подключаемся к серверу

На Windows 10/11 откройте командную строку и введите (вместо `1.2.3.4` — IP вашего сервера):

```bash
ssh root@1.2.3.4
```

На вопрос `Are you sure you want to continue connecting` ответьте `yes`, затем введите пароль (символы при вводе не отображаются — это нормально).

### 2. Устанавливаем Python

```bash
sudo apt update
```

```bash
sudo apt install -y python3 python3-venv python3-pip
```

Проверьте версию:

```bash
python3 --version
```

Нужен Python **3.10 или новее** (рекомендуется 3.11+). На Ubuntu 24.04 будет 3.12, на 22.04 — 3.10: оба варианта подходят.

### 3. Создаём пользователя для бота

Запускать бота от `root` небезопасно, поэтому создадим отдельного пользователя `chisto`:

```bash
sudo useradd --system --create-home --shell /usr/sbin/nologin chisto
```

### 4. Загружаем файлы бота на сервер

**Вариант А — программой WinSCP** (удобно, с окнами как в Проводнике):

1. Скачайте и установите [WinSCP](https://winscp.net/).
2. Подключитесь: протокол SFTP, адрес — IP сервера, пользователь `root`, пароль от сервера.
3. Справа (сервер) перейдите в папку `/opt`, создайте папку `chisto-bot`.
4. Перетащите в неё файлы бота: `bot.py`, `config.py`, `database.py`, `keyboards.py`, `texts.py`, `texts.yaml`, `requirements.txt`, `.env` и папки `handlers` и `deploy`.
   Папку `venv` копировать **не нужно**.

**Вариант Б — командой** из командной строки Windows (в папке, где лежит `chisto-bot`):

```bash
scp -r chisto-bot root@1.2.3.4:/opt/
```

(Если вместе с папкой скопировалась `venv` с Windows — на сервере удалите её командой `sudo rm -rf /opt/chisto-bot/venv`.)

Проверьте, что файл `.env` на месте и в нём правильные токен и ID:

```bash
sudo nano /opt/chisto-bot/.env
```

### 5. Устанавливаем зависимости на сервере

```bash
cd /opt/chisto-bot
```

```bash
sudo python3 -m venv venv
```

```bash
sudo venv/bin/pip install -r requirements.txt
```

Отдаём папку пользователю `chisto` (чтобы бот мог записывать базу заявок) и закрываем `.env` от посторонних:

```bash
sudo chown -R chisto:chisto /opt/chisto-bot
```

```bash
sudo chmod 600 /opt/chisto-bot/.env
```

Пробный запуск (остановить — `Ctrl+C`):

```bash
sudo -u chisto venv/bin/python bot.py
```

Если появилось «Бот @... запущен» — всё работает. Остановите его `Ctrl+C` и переходите к следующему шагу.

> ⚠️ Одновременно может работать только **одна копия** бота. Если бот запущен у вас на компьютере — остановите его там, иначе будет ошибка `Conflict: terminated by other getUpdates request`.

### 6. Делаем службу systemd — бот работает 24/7

systemd — встроенный в Ubuntu «диспетчер», который запустит бота при включении сервера и перезапустит его, если он упадёт.

Готовый файл службы уже лежит в проекте: `deploy/chisto-bot.service`. Скопируйте его в систему:

```bash
sudo cp /opt/chisto-bot/deploy/chisto-bot.service /etc/systemd/system/
```

Включите и запустите службу:

```bash
sudo systemctl daemon-reload
```

```bash
sudo systemctl enable --now chisto-bot
```

Проверьте, что бот работает (должно быть `active (running)` зелёным; выйти — клавиша `q`):

```bash
sudo systemctl status chisto-bot
```

Готово! Теперь можно закрыть окно — бот продолжит работать.

### Полезные команды на сервере

| Что сделать | Команда |
|---|---|
| Посмотреть состояние | `sudo systemctl status chisto-bot` |
| Смотреть логи в реальном времени (выход — `Ctrl+C`) | `sudo journalctl -u chisto-bot -f` |
| Последние 100 строк логов | `sudo journalctl -u chisto-bot -n 100` |
| Перезапустить (после замены `.py`-файлов или `.env`) | `sudo systemctl restart chisto-bot` |
| Остановить | `sudo systemctl stop chisto-bot` |
| Отключить автозапуск | `sudo systemctl disable chisto-bot` |

- **Изменили `texts.yaml`** — перезапуск не нужен, отправьте боту `/reload`.
- **Изменили код (`.py`) или `.env`** — нужен `sudo systemctl restart chisto-bot`.
- Если загружали файлы через WinSCP под `root`, после загрузки повторите `sudo chown -R chisto:chisto /opt/chisto-bot`.

### Резервная копия заявок

Все заявки хранятся в файле `/opt/chisto-bot/leads.db`. Время от времени скачивайте его через WinSCP к себе на компьютер. Открыть файл можно бесплатной программой [DB Browser for SQLite](https://sqlitebrowser.org/).

## Частые проблемы

| Сообщение / ситуация | Что делать |
|---|---|
| `ОШИБКА НАСТРОЙКИ: не указан BOT_TOKEN` | Нет файла `.env` или в нём пустой токен. См. шаг 5. Проверьте, что файл называется именно `.env`, а не `.env.txt`. |
| `ADMIN_ID должен быть числом` | В `.env` после `ADMIN_ID=` должно быть только число из @userinfobot. |
| `Неверный BOT_TOKEN` | Токен скопирован с ошибкой. Скопируйте его заново из @BotFather. |
| `Ошибка в texts.yaml` при запуске | Проверьте отступы (только пробелы) и кавычки в том месте, которое указано в ошибке. |
| Заявки не приходят администратору | Откройте своего бота со своего аккаунта и нажмите **Start**. Проверьте `ADMIN_ID`. Заявки при этом не теряются — смотрите `/leads`. |
| `/leads` и `/reload` не работают | Эти команды работают только для аккаунта, чей ID указан в `ADMIN_ID`. |
| `Conflict: terminated by other getUpdates request` | Бот запущен в двух местах одновременно. Остановите лишнюю копию. |
| `python` не найден на Windows | Переустановите Python с галочкой «Add python.exe to PATH». |

## Из чего состоит проект

```
chisto-bot/
├── bot.py               — запуск бота (с этого файла всё начинается)
├── config.py            — чтение настроек из .env
├── texts.py             — загрузка и проверка texts.yaml
├── texts.yaml           — ВСЕ тексты, услуги, FAQ и контакты (правит заказчик)
├── database.py          — сохранение заявок в SQLite (leads.db)
├── keyboards.py         — кнопки бота
├── handlers/            — обработчики команд и кнопок
│   ├── __init__.py      — порядок подключения обработчиков
│   ├── common.py        — /start, меню, услуги, FAQ, контакты
│   ├── lead_form.py     — пошаговая форма заявки (FSM) и проверка телефона
│   └── admin.py         — /leads и /reload для администратора
├── deploy/
│   └── chisto-bot.service — служба systemd для сервера
├── requirements.txt     — список нужных библиотек
├── .env.example         — образец настроек (скопировать в .env)
├── .gitignore           — что не попадает в git (.env и база)
└── leads.db             — база заявок (создаётся сама при первом запуске)
```

**Про незаконченные заявки:** шаг, на котором клиент заполняет форму, хранится в памяти бота. Если бот перезапустить, незаконченные заявки сбросятся — клиенту нужно будет начать заново через /start. Отправленные заявки хранятся в базе и не пропадают.
